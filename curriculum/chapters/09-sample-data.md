:::note

- 비교 화면의 조건 검사·지표·점수·상충 경고를 근거로 승격 여부를 결정한다

## 들어가기

06장과 08장에서 여러 번 실험했습니다. 앱에는 여러분의 세션 외에도 번들 시뮬레이션 샘플과, 이전 학기에 엑셀로 남긴 실험 데이터가 들어 있습니다. 데이터가 많아지면 새로운 질문이 생깁니다.

오늘의 질문: **"여러 실험 중 '가장 좋은' 것은 무엇이고, 그 판단은 얼마나 믿을 만한가?"**

이 챕터에는 새 실험이 없습니다. 이미 있는 데이터를 **읽고, 고르고, 비교하는** 법을 배웁니다. 하드웨어가 없어도 처음부터 끝까지 할 수 있습니다.

## 1. 좋은 데이터란 무엇인가

좋은 응답(오버슈트가 작은 응답)과 좋은 **데이터**는 다릅니다. 데이터가 좋으려면

| 조건 | 왜 필요한가 |
|---|---|
| 조건이 기록되어 있다 (제어기, 게인, 설정값 프로파일, 서보, 샘플 주기, 필터 α) | 무엇을 했는지 모르면 결과를 재현하거나 비교할 수 없다 |
| 센서 유실이 적다 (5% 이하) | 유실 구간의 지표는 믿기 어렵다 |
| 포화가 적다 (10% 이하) | 명령이 한계에 붙어 있으면 제어기가 아니라 각도 한계가 응답을 만든 것이다 |
| 스텝이 충분히 크다 (15 mm 이상) | 센서 분해능 3 mm에 비해 너무 작으면 오버슈트 %가 잡음에 묻힌다 |
| 출처가 표시되어 있다 (`실측` / `시뮬레이션`) | 시뮬레이션은 모델이 만든 데이터다(08장) |

**이 시스템에서의 의미**: 앱은 위 조건 중 숫자로 확인할 수 있는 것(스텝 크기, 유실, 포화)을 자동 검사하고, 기록되지 않은 조건은 `조건 불명` 배지로 표시합니다. 검사마다 결과가 다르게 처리됩니다.

| 검사 | 걸리면 | 코드 |
|---|---|---|
| 같은 묶음(제어기·설정값 프로파일)인가 | 점수 계산에서 빠짐("다른 묶음") | `best.score` |
| 스텝 크기(목표 − 시작의 크기) ≥ 15 mm | 지표 자체를 계산하지 않음(`small_step`) | `metrics.MIN_STEP_MM` |
| 유실 ≤ 5% | 자격 미달 → 순위 제외 | `best.MAX_LOST` |
| 포화 ≤ 10% | 자격 미달 → 순위 제외 | `best.MAX_SAT` |
| 포화·유실 비율을 **알 수 없음**(제어 입력 기록 없음 등) | "확인 불가"로 표시하고 **후보에는 남김** | `best.eligibility` |

![세션이 최고 사례 점수에 들어가기까지의 검사 흐름. 같은 묶음인지, 스텝 15 mm 이상인지, 유실 5% 이하인지, 포화 10% 이하인지 차례로 검사한다. 포화 기록이 없으면 확인 불가로 표시하고 후보에 남긴다. 슬롯 대표의 계층과 비교 화면의 조건 검사는 점수와 따로 본다](assets/09-sample-data/data-check.svg "그림 1. 자격 검사 흐름(앱의 검사 순서): 좋은 응답보다 좋은 데이터가 먼저다.")

"확인 불가"는 통과가 아닙니다. 점수표의 `자격` 칸에 이유가 적히므로, 그 후보가 1등이라면 직접 그래프를 열어 포화나 유실이 없었는지 확인하세요.

## 3. 엑셀 유래 샘플: 왜 순위에 넣지 않는가

`pid-legacy` 슬롯에는 이전 실험의 엑셀 시트를 변환한 샘플이 들어 있습니다 [실측].

:::widget overlay-plot {"sources": ["slot:pid-legacy", "sample:real-xlsx-pd_f1", "sample:real-xlsx-pid_f1", "sample:real-xlsx-pid_f2"], "signals": ["y_mm", "ref_mm"], "align": "start", "show_metrics": true, "caption": "엑셀 유래 실측 샘플(조건 불명, 시간축 추정)"}:::

이 샘플들은 **실측**이지만 다음 이유로 여러분의 세션과 우열을 매기지 않습니다.

1. **게인 단위가 확실하지 않습니다.** 시트에 적힌 게인(예 2.3884)이 SI(rad/m)인지 °/cm인지 모릅니다(06장 2.1절). 두 해석은 1.745배 차이입니다.
2. **시간축을 추정했습니다.** 원본에 시간 열이 없어 50 ms 간격을 가정했습니다 [가정]. 실제가 60 ms였다면 모든 시간 지표가 20% 틀립니다.
3. **설정값과 출발점이 다릅니다.** 다섯 개 모두 220 mm 고정 설정값이고, 이 교재의 표준 스텝(150 → 200 mm)이 아닙니다. 게다가 출발점이 48 mm, 61 mm, 253 mm로 제각각이라 스텝 크기가 +172 mm에서 −33 mm까지 다릅니다(그림 2).
4. `real-xlsx-pd_f2`는 다른 시트(`PID_f1`)를 잘라 낸 사본으로 의심됩니다(`중복 의심`: A열 932행이 `PID_f1` 앞부분과 같음). `PID_f2` 시트의 메모 지표도 `PD_f2`와 똑같아 복사가 의심됩니다.

![엑셀 유래 실측 다섯 개의 위치 기록. 왼쪽 세 개는 48~61 mm에서 출발해 220 mm로 올라가고, 오른쪽 두 개는 253 mm에서 출발해 33 mm 내려가며 서로 겹친다](assets/09-sample-data/legacy-start.svg "그림 2. 엑셀 유래 샘플: 설정값은 같아도 출발점이 달라 스텝 크기가 제각각이다 [실측, 시간축 50 ms 가정].")

같은 데이터에서 앱이 계산한 지표를 보면 비교할 수 없는 이유가 숫자로 드러납니다 [실측, 앱 `metrics` 계산, 시간축 가정]:

| 샘플 | 시트에 적힌 게인 ($K_p$, $K_i$, $K_d$) | 출발 → 설정값 | 앱 P.O. | 시트 메모 P.O. |
|---|---|---|---|---|
| `real-xlsx-pd_f1` | 2.3884, 0, 2.0684 (슬라이드 48과 같은 숫자) | 48 → 220 mm | 77% | 24.3% |
| `real-xlsx-pid_f2` | 0.27276, 0.015784, 1.1784 | 48 → 220 mm | 44% | 24.3% |
| `real-xlsx-fil_pd_ex1` | 5.4586, 0, 2.4395 | 61 → 220 mm | 49% | 31.1% |
| `real-xlsx-pd_f2` | 0.6, 0, 1.05 | 253 → 220 mm | 394% | 24.3% |
| `real-xlsx-pid_f1` | 1.0632, 0.11983, 2.3584 | 253 → 220 mm | 305% | 14.8% |

- 오버슈트 %는 스텝 크기로 나눈 값입니다. 33 mm 스텝에서는 100 mm만 지나쳐도 300%가 넘습니다. 15 mm 하한은 넘으므로 앱은 계산하지만, 표준 스텝(50 mm)의 %와 나란히 놓을 수 없습니다.
- 시트 메모의 지표는 어떤 정의·구간으로 계산했는지 기록이 없어(출처 미상) 앱은 쓰지 않습니다. 같은 기록인데 77%와 24.3%처럼 크게 다른 것은 **지표의 정의를 모르면 숫자를 믿을 수 없다**는 예입니다.
- `pd_f1`의 게인 숫자는 슬라이드 48 PD와 같지만, 단위가 불명이라 04·05장의 계산과 이 기록을 이어 붙일 수 없습니다(1번 이유).
- 이 샘플들을 내 표준 스텝 세션과 비교 화면에 올리면 조건 검사가 `조건 불명`이 됩니다. 다른 항목은 출처(실측 대 시뮬레이션), 설정값 프로파일, 샘플 주기(가정)이고, 서보 모델·모델 종류는 기록이 없습니다.

:::note
그렇다고 이 데이터가 쓸모없는 것은 아닙니다. 그래프의 **모양**(진동 주기, 정상상태 오차가 남는지, 센서 튐)은 여전히 실제 장치의 특징을 보여 줍니다. "비교할 수 없다"와 "배울 것이 없다"는 다른 말입니다.
:::

## 4. 최고 사례 선정 규칙

앱의 "최고 사례"는 다음 규칙으로 정합니다.

1. **같은 묶음**만 비교: 같은 제어기, 같은 설정값 프로파일.
2. **자격 검사**: 포화 비율 10% 이하, 센서 유실 5% 이하.
3. 지표 네 개(ITAE, 정착시간 $t_s$, 오버슈트 P.O., 제어 총변동 $u_{tv}$)를 후보 안에서 **min-max 정규화**합니다. 가장 좋은 값이 0, 가장 나쁜 값이 1입니다.

$$\text{norm}_i = \frac{x_i - x_{min}}{x_{max} - x_{min}}$$

4. 가중합 점수가 **가장 낮은** 후보가 1등입니다.

$$\text{점수} = 0.4\,\text{norm}(ITAE) + 0.3\,\text{norm}(t_s) + 0.2\,\text{norm}(P.O.) + 0.1\,\text{norm}(u_{tv})$$

**이 시스템에서의 의미**: ITAE는 늦게 남은 오차를 더 무겁게 벌주므로 "빨리, 그리고 끝까지 정확히 가는가"를 봅니다. $u_{tv}$는 서보를 얼마나 떨게 했는지를 봅니다.

앱(`store/best.js`)이 따로 처리하는 경우:

| 경우 | 처리 |
|---|---|
| 정착하지 못한 세션의 $t_s$ | 묶음의 최댓값으로 보아 정규화 값 1(가장 나쁨) |
| 어떤 후보에 지표 하나가 아예 없음(예: 제어 입력 기록이 없어 $u_{tv}$ 없음), 또는 모든 후보가 미정착 | 그 지표를 빼고, 남은 가중치를 합이 1이 되게 다시 나눔(비교 화면에 "뺀 항목"으로 표시) |
| 모든 후보의 값이 같음($x_{max} = x_{min}$) | 모두 0 |
| 가중치의 합이 1이 아님(슬라이더) | 합으로 나눠 씀. 예: ITAE 1.0만 주면 ITAE 하나로만 순위 |

### 4.1 손으로 한 번 계산하기

| 후보 | ITAE | $t_s$ (s) | P.O. (%) | $u_{tv}$ (°) |
|---|---|---|---|---|
| A | 200 | 3.0 | 10 | 5 |
| B | 150 | 4.0 | 20 | 8 |
| C | 300 | 2.5 | 5 | 3 |

[가정: 계산 연습용 숫자. 크기는 번들 샘플과 비슷하게 잡았다(ITAE 99~198, $u_{tv}$ 7~15°)]

A의 정규화 값은 ITAE (200 − 150)/(300 − 150) = 0.333, $t_s$ (3.0 − 2.5)/(4.0 − 2.5) = 0.333, P.O. (10 − 5)/(20 − 5) = 0.333, $u_{tv}$ (5 − 3)/(8 − 3) = 0.4이므로 점수는 0.4·0.333 + 0.3·0.333 + 0.2·0.333 + 0.1·0.4 = **0.34**입니다. B와 C도 계산해 1등을 정해 보세요(워크시트). 정규화는 비율이므로 지표의 단위(°든 rad든)는 점수에 영향을 주지 않습니다.

![4.1절 예의 후보 A 점수 0.34를 지표별 기여로 쌓은 막대. 후보 B와 C는 빈 막대로 두어 워크시트에서 직접 계산하게 했다](assets/09-sample-data/score-stack.svg "그림 3. 가중합 점수 쌓아 보기: 후보 A = 0.34. B와 C는 직접 계산한다 [가정: 계산 연습용 숫자].")

:::predict p1
가중치를 ITAE 하나에만 모두(1.0) 주면 1등은 A, B, C 중 누구일까요?
:::

슬라이더로 가중치를 바꿔 위 예와 `pid-best` 슬롯의 순위가 어떻게 바뀌는지 보세요. **가중치는 하나의 선택일 뿐입니다.** "오버슈트가 절대 안 되는 응용"이라면 P.O. 가중치를 키우는 것이 맞습니다. 가중치를 정하는 것은 계산이 아니라 **판단**입니다.

## 5. 좋은 사례와 나쁜 사례: 지표만 보면 놓치는 것

지표 표만 보고 판단하면 놓치는 경우가 있습니다.

| 경우 | 지표에 보이는 것 | 놓치는 것 | 확인하는 법 |
|---|---|---|---|
| 포화로 만든 빠른 응답 | 상승시간이 짧다 | 명령이 각도 한계에 붙어 있어, 한계를 바꾸면 결과가 달라진다 | 자격 검사(포화 10%)가 거른다. `u_cdeg`가 한계에 붙어 있는지 그래프로 |
| 정착 후 잔진동 | $t_s$·ITAE가 좋다 | 5% 밴드(표준 스텝에서 ±2.5 mm) 안에서 계속 흔들려 서보가 쉬지 않는다 | $u_{tv}$와 그래프를 같이 본다 |
| 잡음이 띠를 건드림 | 느리게 다가가는 응답이 "미정착"으로 나온다 | 응답은 매끄러운데 ±1 mm 잡음이 ±2.5 mm 띠를 넘나든다(08장 7절의 재설계 샘플) | `y_filt_mm`과 띠를 겹쳐 본다 |
| 운 좋은 한 번 | 한 번의 1등 | 같은 게인이라도 시작 위치와 잡음에 따라 지표가 달라진다 | 반복 실행의 평균·편차(10장) |

:::predict p2
ITAE는 가장 좋지만 그래프를 보니 5% 밴드 안에서 잔진동이 계속되는 세션이 있습니다. 이 세션을 최고 사례로 승격해야 할까요? 이유와 함께 쓰세요.

## 6. 비교 화면 읽기: "새 샘플이 정말 더 좋은가?"

06장에서 처음 본 승격 대화상자의 비교 화면을 이제 자세히 읽습니다. 아래는 08장 재설계 PID의 대표 샘플을 06장 최고 PID와 비교한 화면입니다.

:::widget sample-compare {"candidate": "slot:pid-servo-redesign", "targets": ["slot:pid-best"], "metrics": ["tr", "tp", "po", "ts", "ess", "iae", "itae", "u_rms", "u_tv", "u_sat_ratio", "lost_ratio"]}:::

위에서부터 순서대로 읽습니다.

| 순서 | 화면 | 읽는 법 |
|---|---|---|
| 1 | **조건 검사** | 데이터 출처(실측/시뮬레이션), 제어기, 설정값 프로파일, 서보 모델, 샘플 주기, 모델 종류를 대조합니다. 하나라도 다르면 `조건 상이`, 기록이 없으면 `조건 불명`이고, 이때는 우열 기호(▲▼)를 **표시하지 않습니다**. 시간축을 가정한 샘플은 샘플 주기가 "다름"으로 처리됩니다. |
| 2 | **겹친 그래프** | 후보(굵게)와 비교 대상, 같은 슬롯의 다른 샘플(옅게). 스텝 시작 시각에 맞춰 겹칩니다. |
| 3 | **지표 표** | 항목마다 ▲(후보가 좋음) ▼(나쁨) =(차이 1% 미만)와 차이 % = (후보 − 대상) ÷ 대상의 크기. 모든 지표는 작을수록 좋습니다. |
| 4 | **점수표** | 원값, 정규화 값, 실제로 쓴 가중치, 자격(적격/제외/확인 불가)을 모두 공개합니다. |
| 5 | **상충 경고** | 점수와 개별 지표의 우열이 엇갈리면 "점수 열세, 오버슈트 −48% 우위"처럼 경고가 뜹니다. |

**번들 샘플로 보면** (두 슬롯에 아직 내 샘플을 승격하지 않았을 때: 후보 `sim-pid-servo-redesign` (0.5, 1.25), 대상 `sim-pid-p1` (1.0, 1.5), 둘 다 `시뮬레이션`) [시뮬레이션: `samples.compare`]:

| 지표 | 후보 | 대상 | 기호 |
|---|---|---|---|
| 조건 검사 | | | `조건 일치` |
| $t_r$ | 2.31 s | 1.30 s | ▼ +78% |
| P.O. | 5.2% | 10% | ▲ −48% |
| $t_s$ | 미정착 | 5.64 s | (값 없음) |
| ITAE | 198.1 | 98.8 | ▼ +100% |
| $u_{rms}$ / $u_{tv}$ | 0.56° / 7.2° | 1.10° / 14.8° | ▲ −49% / ▲ −51% |
| 정규화 (ITAE / $t_s$ / P.O. / $u_{tv}$) | 1 / 1 / 0 / 0 | 0 / 0 / 1 / 1 | |
| 점수 | **0.70** (2등) | **0.30** (1등) | |

상충 경고는 "점수 열세, 오버슈트 −48% 우위, u_rms −49% 우위, u_tv −51% 우위"입니다. 후보가 둘뿐이면 정규화 값이 0 아니면 1이라, 점수는 "내가 진 지표의 가중치 합"이 됩니다(후보: ITAE 0.4 + $t_s$ 0.3 = 0.70). 둘을 비교할 때는 점수보다 지표 표와 상충 경고가 더 많은 것을 알려 줍니다. 이 결과를 보고 "재설계가 실패했다"고 말할 수는 없습니다. 오버슈트와 제어 노력을 반으로 줄이는 대신 빠르기를 내준 **다른 절충**입니다(08장 5절).

:::warning
점수는 같은 묶음 **안에서** 정규화한 값이라, 후보가 하나 추가되면 기존 후보들의 점수도 바뀝니다. 순위까지 뒤집힐 수 있습니다(그림 4). "점수 0.34"를 다른 묶음의 0.34와 비교하지 마세요.
:::

## 생각해 보기

채점하지 않는 질문입니다. 답을 먼저 적어 보고, 막히면 아래 실마리를 열어 보세요.

1. 본문 4.1절 표의 후보 B의 점수는? (기본 가중치 0.4/0.3/0.2/0.1, 소수 둘째 자리)
2. 같은 표에서 가중치를 ITAE 0.1, t_s 0.2, P.O. 0.6, u_tv 0.1로 바꾸면 1등은? (보기: A / B / C)
3. 엑셀 유래 샘플(real-xlsx-*)을 내 표준 스텝 세션과 우열 비교하지 않는 가장 중요한 이유는? (보기: 실측이 아니므로 / 게인 단위·시간축·설정값 등 조건이 불명이거나 달라서 / 데이터가 오래되어서 / 엑셀 형식이라 정밀도가 낮아서)
4. 포화 비율 15%, 유실 1%인 세션의 ITAE가 묶음에서 가장 작다. 최고 사례 선정에서 이 세션은? (보기: 1등이 된다 / 자격 검사에서 제외된다 / 점수에 벌점을 받는다 / 유실이 적어서 가산점을 받는다)
5. 승격 비교 화면의 조건 검사가 대조하는 항목을 모두 고르라. (보기: 제어기 / 설정값 프로파일 / 서보 모델 / 샘플 주기 / 실험한 학생 이름 / 모델 종류 / 데이터 출처(실측·시뮬레이션))
6. 후보 세션이 점수는 기존 샘플보다 낮지만(우위) 오버슈트는 4%p 크다. 승격(교체), 별도 추가, 보류 중 무엇을 고르겠는가? 근거를 쓰라.

:::details 생각의 실마리 (스스로 답을 적어 본 뒤 열기)
1. B의 정규화 값: ITAE 0, t_s 1, P.O. 1, u_tv 1 → 0.4·0 + 0.3·1 + 0.2·1 + 0.1·1 = 0.60. A = 0.34, C = 0.40이므로 1등은 A.

3. 엑셀 샘플은 실측이지만 게인 단위(rad/m인지 °/cm인지), 샘플 주기(50 ms 가정), 설정값(220 mm 고정)이 다르거나 불명이다. 조건이 다르면 우열을 단정할 수 없다.

5. 조건 검사는 실험 결과에 영향을 주는 조건(데이터 출처, 제어기, 프로파일, 서보, 샘플 주기, 모델 종류)을 본다. 실측과 시뮬레이션은 조건이 같아도 우열을 매기지 않는다. 누가 실험했는지는 조건이 아니다.
6. 정답은 하나가 아니다. 예: 응용에서 오버슈트가 중요하지 않고 조건이 같으며 반복 시행에서도 우위가 유지되면 교체. 오버슈트 제한이 중요한 응용이거나 시행이 한 번뿐이라면 별도 추가 또는 보류. 핵심은 조건 동일 여부, 상충하는 지표의 중요도, 시행 횟수를 근거로 드는 것이다.

## 요약과 다음 챕터

- 좋은 응답과 좋은 데이터는 다르다. 조건 기록, 유실·포화 검사, 출처 표시가 먼저다.
- 최고 사례는 같은 묶음 안에서 정규화한 가중합 점수로 고르며, 가중치는 판단의 문제다. 정규화가 후보 안에서만 이뤄지므로 후보가 바뀌면 순위도 바뀔 수 있고, 후보가 둘이면 점수보다 지표 표와 상충 경고를 본다.
- 엑셀 유래 실측은 조건 불명(게인 단위, 시간축, 출발점이 제각각인 스텝)이라 우열 비교에서 빠지지만, 응답의 모양에서 배울 것은 있다.
- 승격은 조건 검사 → 지표 → 점수 → 상충 순서로 근거를 확인하고 결정한다.
