# 디지털 트윈으로 제어기 시험하기

:::part theory

:::note
**이 장의 목표**
- 설계 모델, 가상 장치, 디지털 트윈, 실제 장치가 어떻게 다른지 설명하고, 설계 모델로만 시험하면 모델 오차가 보이지 않는 이유를 말한다
- 트윈의 공·서보·센서 식이 설계 모델에 무엇을 더했는지 읽고, 선형 극한에서 설계 모델로 돌아간다는 것을 확인한다
- 같은 제어기를 설계 모델과 트윈에서 돌려 오버슈트·정착시간·ITAE 등 지표의 차이를 기록하고 원인 가설을 세운다
- 공 밀기 외란과 센서 고장(이상값·유실·멈춤)에 대한 응답과 폴백 동작을 관찰한다
- 몬테카를로 강건성 시험(n = 30)의 성공률로 강건성을 판단하고, 공칭 1회 성공과 구분하며, 결과를 '가정 파라미터, 실측 미검증' 조건과 함께 보고한다
:::

:::warning
**이 장의 모든 그래프와 숫자는 `[시뮬레이션]`이고, 트윈 파라미터는 모두 `[가정]`입니다.** 트윈이 실제 장치의 **동특성(공 응답)을 얼마나 닮았는지는 실측으로 검증하지 않았습니다(실측 미검증).** 그래서 이 장의 결과는 "가정한 비이상성 아래에서 제어기끼리의 상대 비교"로만 읽습니다. 제어기 우열의 실측 근거로 쓰지 않습니다.

## 들어가기

06장에서 "실측은 서보 무시 예측보다 더 진동한다"를 보았고, 08장에서 서보를 모델에 넣어 차이의 큰 부분을 설명했습니다. 그런데 서보를 넣은 모델도 여전히 **선형**입니다. 마찰도, 서보의 작은 유격도, 초음파가 가끔 엉뚱한 거리를 내는 일도 들어 있지 않습니다.

실제 장치에서 이런 것들을 하나씩 시험하려면 시간이 많이 듭니다. 공을 수십 번 밀고, 서보를 느린 것으로 바꾸고, 센서를 일부러 가려야 합니다. 장치는 조당 하나뿐이고, 실패하면 공이 굴러떨어집니다.

**디지털 트윈**은 이 일을 화면 안에서 하게 해 줍니다. 오늘의 질문:

**"설계 모델로 만든 게인이, 실제와 닮은(그러나 설계 모델과는 다른) 시스템에서 어디까지 버티는가?"**

## 1. 설계 모델, 가상 장치, 트윈, 실제 장치

| 구분 | 무엇을 돌리나 | 무엇을 배우나 | 결과 배지 |
|---|---|---|---|
| 설계 모델 | $P(s) = G_{servo}(s)\,K_b/s^2$ (선형) | 근궤적·보드·LQR 설계(04·05·08·13장) | 시뮬레이션 |
| 가상 장치 (`virtual`) | **설계 모델과 같은 식**에 잡음·60 ms 샘플링 | 실습 절차, 프로토콜, 화면 따라하기 | 시뮬레이션 |
| 디지털 트윈 (`twin`) | 설계 모델과 **일부러 다른** 비선형 + 비이상성 물리 | 모델 불일치, 외란, 파라미터 변동, 센서 고장 | 디지털 트윈 + 시뮬레이션 |
| 실제 장치 (`device`) | 진짜 공과 서보 | 모든 것 | 실측 |

가상 장치에서 잘 되는 게인은 "설계가 계산대로 되었다"는 뜻일 뿐입니다. 시험지를 만든 사람이 자기 답안지로 채점하는 것과 같아서, **모델이 틀린 부분은 영원히 보이지 않습니다.** 트윈은 설계 모델에 없는 효과를 일부러 넣어 그 빈틈을 드러냅니다.

![위 줄은 설계 모델로, 서보 1차+지연, K_b/s², 센서 필터 세 블록뿐이다. 아래 줄은 디지털 트윈으로, 호스트 정수 명령·통신 지연, PWM 프레임, 서보 데드밴드, 링크 백래시, sin 레버와 수평 오차, 마찰·멈춤판이 있는 공, 잡음·이상값·유실이 있는 센서, 트윈 기본(펌웨어 1.0.0 동작)에서는 이상값을 거르지 않는 펌웨어 필터를 거쳐 제어기로 돌아온다. 참 상태는 화면과 채점에만 쓰고 제어기에는 주지 않는다](assets/21-digital-twin/model-gap.svg "그림 1. 설계 모델과 디지털 트윈의 구조(개념도). 제어기는 두 경우 모두 센서 출력만 받는다.")

트윈에서도 제어기는 **센서 출력만** 받습니다. 트윈 안에는 공의 참 위치가 있지만, 그것은 화면의 애니메이션과 채점(성공 판정, ITAE)에만 쓰입니다. 실제 장치에서 제어기가 공의 참 위치를 모르는 것과 같은 조건을 지키기 위해서입니다.

## 2. 트윈의 물리

기호는 03장 `model-derivation`과 같습니다. 식마다 "설계 모델에 무엇이 더해졌나"를 봅니다.

### 2.1 공과 빔

빔 각은 레버를 sin으로 계산하고, 빔의 수평 오차 $\alpha_0$를 더합니다.

$$\sin\alpha_l = \frac{d}{L}\sin\theta_b,\qquad \alpha = \alpha_l + \alpha_0$$

설계 모델은 $\alpha = (d/L)\,\theta$입니다. **이 시스템에서의 의미**: 레버비 $L/d$가 약 6.5라서, 빔이 0.05° 기울어 있으면 서보각으로는 약 0.33°에 해당합니다 `[가정]`. 수평을 아주 조금만 잘못 맞춰도 서보가 그만큼 계속 기울어 있어야 공이 멈춥니다.

공의 운동방정식은 설계 모델의 $\ddot y = K_b\,\theta$에 마찰·감쇠·원심 항·외력을 더한 것입니다.

$$m_{\text{eff}}\,\ddot y = m g\sin\alpha - \mu_r m g\cos\alpha\,\tanh\!\left(\frac{\dot y}{\varepsilon}\right) - m_{\text{eff}}\,b\,\dot y + m\,(y - y_p)\,\dot\alpha^2 + m\,a_{\text{ext}}$$

여기서 $m_{\text{eff}} = m(1+\kappa)$, $\kappa = J/(mR^2)$입니다. 두 번째 항은 구름 마찰(쿨롱 마찰을 매끄럽게 근사), 세 번째는 점성 감쇠, 네 번째는 빔이 돌 때의 원심 항, 마지막은 "공 밀기" 같은 외란입니다. 속도가 아주 작고 기울기가 문턱(서보각 약 0.28°)보다 작으면 **정지 마찰**이 공을 붙잡습니다 `[가정]`. 빔 끝 멈춤판에 닿으면 반발계수 $e$ = 0.3으로 튕깁니다.

**이 시스템에서의 의미**: 작은 각도에서 마찰·감쇠·원심 항을 모두 0으로 두면

$$\ddot y = \frac{g}{1+\kappa}\,\alpha \approx \frac{g\,d}{L(1+\kappa)}\,\theta = K_b\,\theta$$

로 설계 모델의 $K_b/s^2$가 그대로 돌아옵니다. 트윈은 설계 모델을 버린 것이 아니라 **설계 모델을 포함하고 그 위에 효과를 더한 것**입니다. 다만 트윈은 공을 얇은 중공구($\kappa$ = 2/3)로 보아 $K_{b,\text{twin}}$ = 0.8993으로, 설계값 0.8709보다 3.3% 큽니다(03장에서 본 $J$·$R$ 불일치) `[가정]`. 이 3.3%도 트윈이 가진 "모델 오차" 가운데 하나입니다.

### 2.2 서보

명령은 정수 cdeg → 1 µs 단위 펄스 → 20 ms PWM 프레임마다 서보가 읽음 → 내부 지연 $T_d$ → 목표각 $\theta_t$로 갑니다. 모터 출력축 $\theta_m$은

$$e = \theta_t - \theta_m,\qquad \dot\theta_m = \begin{cases} 0, & |e| \le \delta/2 \\ \text{clamp}\!\left(\dfrac{e - \text{sgn}(e)\,\delta/2}{\tau},\ \pm\omega_{max}\right), & \text{그 밖} \end{cases}$$

로 움직이고, 기계 한계 ±40°에서 멈춥니다. 빔을 미는 링크 각 $\theta_b$는 백래시 $\beta$만큼 늦게 따라옵니다(방향이 바뀌면 $\beta$만큼은 링크가 움직이지 않음).

**이 시스템에서의 의미**: 데드밴드 $\delta$ = 0.4°, 백래시 $\beta$ = 0.3°는 **가정값**입니다(제조사 문서로 확인하지 않음) `[가정]`. 이 크기는 06장 PD가 정착할 때 내는 작은 수정 명령과 비슷해서, "거의 다 왔을 때 하는 작은 조정"이 빔에 전달되지 않을 수 있습니다. 또 포텐쇼미터는 $\theta_m$을, 빔은 $\theta_b$를 보므로 서보각을 측정해 쓰는 LQR은 백래시만큼 틀린 각을 받습니다. $\delta = \beta = 0$이고 프레임·양자화를 끄면 08장의 서보 모델(1차 + 지연 + 속도 한계)과 같아집니다.

### 2.3 센서, 펌웨어, 통신

초음파 측정은 약 60 ms마다 하고, 참 위치에 지연 $T_{sensor}$(1.5 ms)·잡음 $\sigma$(2 mm)·1 mm 양자화를 더합니다. 확률 $p_{lost}$ = 0.01로 유실(−1), $p_{out}$ = 0.008로 약 304 mm의 이상값이 나옵니다 `[가정]`. 펌웨어 필터는 02장의 $f \leftarrow f(1-\alpha) + x\alpha$ 그대로이고, 유실이면 직전 값을 유지합니다. 이상값을 어떻게 다루는지는 펌웨어 판에 따라 다릅니다.

- **펌웨어 1.0.0 동작 = 트윈 기본(`despike` 0)**: 이상값을 **그대로 섞습니다**.
- **펌웨어 1.1.0 기본(`despike` 2 = gate)**: 재귀 필터 앞에서, 직전에 받아들인 값보다 60 mm 넘게 벗어난 측정을 최대 3번 연속 버립니다(02장의 거리 이상값 제거). 트윈에서는 `loop.despike`를 2로 둔 시나리오(예: `sensor-fault-gate`)에서만 켜집니다.

브라우저와 장치 사이 통신 지연은 8 ms로 둡니다 `[가정]`.

**이 시스템에서의 의미**: 이상값 304 mm는 유효 범위(20~500 mm) 안이라 앱의 유실 판정으로는 걸러지지 않습니다. 트윈 기본(1.0.0 동작)에서는 펌웨어도 거르지 않으므로, 이상값이 필터 값 `filt_mm`에 섞여 제어기로 들어갑니다. 1.1.0의 gate는 그 앞에 **한 층을 더하지만 `filt_mm`만 지킵니다.** 원측정 `dist_mm`에는 이상값이 그대로 남고, 원측정(`aux.y_raw_m`)을 쓰는 LQR·LQI·SMC는 gate의 보호를 받지 못합니다. 실제로 이 셋의 트윈 결과는 despike 0과 2에서 비트 단위로 같습니다 `[시뮬레이션]`. 또 공이 304 mm 근처(차 60 mm 이하)에 있거나 튐이 4번 이상 이어지면 gate도 통과시킵니다. 트윈 기본을 0으로 둔 것은 이 장의 표를 같은 조건으로 재현할 수 있게 하기 위해서입니다. 그래서 **이 장의 표와 수치는 따로 적지 않으면 despike 0(1.0.0 동작) 결과**이고, 실기 1.1.0과는 조건이 다릅니다(`docs/theory/digital-twin.md` §6.4). 실습 ①·④에서 두 경우를 비교합니다.

## 3. 트윈을 얼마나 믿을 수 있나

트윈에 두 가지 다른 질문을 해야 합니다.

**(1) 식을 코드로 바르게 옮겼나?** 이것은 확인했습니다 `[시뮬레이션]`.
- 선형 극한: 트윈의 모든 비이상성을 끄면 08장 설계 모델과 같은 명령에 대해 공 위치 차이가 최대 8e-17 m(계산 오차 수준)입니다. PD·LQR 폐루프도 같은 결과를 냅니다.
- 보존: 마찰 0, 반발 1로 20 s 동안 멈춤판에 여러 번 부딪혀도 에너지 변화가 5e-7(상대값)입니다. 공은 어떤 경우에도 빔 밖으로 나가지 않습니다.
- 안전 장치: 각도 한계, 하트비트, 비상 정지가 실제 장치와 같은 규칙으로 동작합니다.

**(2) 트윈이 우리 장치를 닮았나?** 이것은 **확인하지 못했습니다.**

:::warning
**동특성 충실도: 실측 미검증.** 트윈의 공 응답을 같은 입력의 실측과 비교한 적이 없습니다. 번들 실측 샘플(엑셀 변환 8개)에는 시간 열과 서보 명령 열이 없고, 게인 단위와 서보 조건도 모르기 때문에 같은 입력으로 비교할 수 없습니다(09장 "조건 불명"). 그래서 오차(RMSE, 시정수, 지연)를 계산하지 않았고, 트윈을 실측에 억지로 맞추지도 않았습니다.

센서 통계만 부분적으로 비교했습니다: 유실·단발 튐 비율은 실측 범위 안이었지만(트윈 값을 그 실측에서 정했으므로 독립 검증이 아님), 잡음 추정은 트윈 1.8~2.4 mm로 실측 2.4~4.8 mm보다 낮았습니다 `[시뮬레이션]` `[실측]`(조건 불명).
:::

트윈이 우리 장치를 닮았는지 확인하려면 이런 실측이 필요합니다: 07장 서보 식별(큰 스텝·아주 작은 스텝·방향 바꾸기 → $\tau$, $T_d$, $\omega_{max}$, $\delta$, $\beta$), 03장 일정 각 굴림(여러 각 → $K_b$, 마찰, $\alpha_0$), 02장 정지 공 측정(→ $\sigma$, 유실·이상값 확률), 그리고 같은 제어기·같은 프로파일의 폐루프 세션. 장치가 있는 조는 워크시트 6절에서 이 일을 시작할 수 있습니다.

:::

6. 트윈의 동특성 충실도를 검증하려면 실제 장치에서 무엇을 재야 하나? 가장 먼저 잴 것 하나를 고르고 이유를 쓰라.

:::details 생각의 실마리 (스스로 답을 적어 본 뒤 열기)
1. 가상 장치는 설계 모델과 같은 식으로 돌기 때문에 모델에 없는 효과(데드밴드, 백래시, 마찰, 이상값)가 결과에 나타날 수 없다. 트윈은 그런 효과를 넣었으므로 "이런 종류의 효과가 있으면 진동한다"는 가능성은 보여 줄 수 있다. 그러나 트윈 값이 가정이므로, 실제 장치에서 그 크기만큼 진동할지는 실측으로만 안다.
2. 트윈 코드가 설계 모델의 식을 바르게 포함한다는 것(적분기·식 구현 검증)을 보인다. 이것이 틀리면 트윈과 설계 모델의 차이가 물리 효과 때문인지 코드 오류 때문인지 가를 수 없다. 그러나 이것은 "식을 바르게 옮겼다"는 검증이지 "장치를 닮았다"는 검증이 아니다. 동특성 충실도는 실측 미검증이다.
3. 예: 같은 시나리오·시드에서 수평 오차 $\alpha_0$만 0으로(또는 ±0.1°로) 바꿔 정상상태 오차가 따라 변하는지 본다. 다른 효과(마찰, 데드밴드)는 그대로 둔다. 한 번에 하나만 바꾼다(06장 원칙).
4. 예: (a) 트윈 파라미터는 가정값이고 동특성은 실측 미검증이다. (b) 순위가 가정한 $\alpha_0$·$\mu_r$·$\delta$에 민감하다. (c) 한 시나리오(step-nominal), n = 30, 정해진 변동 범위와 성공 기준(10 mm)의 결과다. (d) LQI는 07장 서보 모델과 포텐쇼미터 캘리브레이션에 의존하므로 그것이 틀리면 결과가 달라질 수 있다. (e) 제어 노력·튜닝 노력·설명 가능성(15·20장)은 보지 않았다.
5. 문턱은 한 샘플(60 ms) 동안 공이 정상적으로 갈 수 있는 거리보다 커야 한다(그렇지 않으면 공 밀기 같은 진짜 빠른 움직임까지 버린다). "최대 3번"은 계속 버리기만 하다가 진짜 큰 움직임을 영영 놓치지 않게 하는 상한이다(4번째는 받아들인다). 막지 못하는 경우: (a) 원측정 `dist_mm`을 쓰는 LQR·LQI·SMC는 gate를 거치지 않는다 — 제어기 안에서 같은 규칙을 원측정에 적용하거나, 관측기에서 "측정 − 예측"이 너무 크면 그 측정을 쓰지 않게 할 수 있다(이 앱의 제어기에는 아직 없다). (b) 공이 304 mm 근처(차 60 mm 이하)에 있으면 튐과 정상 측정을 구별하지 못한다. (c) 튐이 4번 이상 이어지면 받아들인다. 그 밖에 치우침·멈춤처럼 값이 "그럴듯한" 고장도 gate로는 못 막는다. 트윈 기본(despike 0)에서는 gate 층 자체가 꺼져 있다는 점도 함께 적으면 좋다.
6. 예: 07장 서보 식별(스텝 크기를 바꿔 $\tau$, $T_d$, $\omega_{max}$, 아주 작은 스텝으로 데드밴드, 방향 바꾸기로 백래시). 서보 경로는 모든 제어기의 위상여유에 영향을 주고, 앱이 식별 결과를 트윈에 자동으로 넣어 주므로 가장 먼저 `[가정]`을 `[실측]`으로 바꿀 수 있다. 또는 03장 일정 각 굴림으로 $\alpha_0$와 마찰을 재는 것도 좋은 답이다(PD 실패의 주원인 후보).

## 용어 정리

| 용어 | 뜻 (이 교재에서) |
|---|---|
| 설계 모델 | 제어기를 만들 때 쓴 선형 모델 $G_{servo}(s)K_b/s^2$ |
| 가상 장치 | 설계 모델과 같은 식으로 도는 시뮬레이션 장치(`virtual`) |
| 디지털 트윈 | 설계 모델과 일부러 다른 비선형·비이상 물리로 도는 가상 장치(`twin`) |
| 참 상태 / 센서 출력 | 트윈 안의 실제 공 위치·각도(화면·채점용) / 제어기가 받는 측정값 |
| 데드밴드 $\delta$ | 서보가 반응하지 않는 작은 명령 차이 |
| 백래시 $\beta$ | 방향이 바뀔 때 링크가 움직이지 않는 유격 |
| 선형 극한 | 트윈의 비이상성을 모두 끈 상태. 설계 모델과 같아야 한다 |
| 몬테카를로 시험 | 파라미터를 범위 안에서 무작위로 바꾼 여러 트윈에서 같은 제어기를 실행해 분포를 보는 시험 |
| 성공률 | 마지막 2 s 참 위치 오차 ≤ 10 mm, 멈춤판 충돌·발산 없이 끝난 표본의 비율 |
| 이상값 제거 (despike, gate) | 펌웨어 1.1.0이 재귀 필터 앞에서 튄 측정을 버리는 기능. 기본 2 = gate(직전 채택값에서 60 mm 넘게 벗어난 값을 최대 3번 연속 버림). `filt_mm`에만 작용. 트윈 기본은 0(끔, 1.0.0 동작) |
| 폴백 | 정상 경로가 실패했을 때 대신 쓰는 동작(직전 u 유지, 관측기 예측, 하트비트 정지 등) |
| 충실도 | 트윈이 실제 장치를 닮은 정도. 이 교재의 트윈은 **동특성 실측 미검증** |

## 요약과 다음 단계

- 설계 모델 위에서만 시험하면 모델 오차가 보이지 않는다. 트윈은 설계 모델을 포함하고(선형 극한), 그 위에 마찰·수평 오차·데드밴드·백래시·센서 이상값을 더한다.
- 공칭 트윈에서 모든 번들 제어기의 ITAE가 설계 예측의 1.4~6.4배였다. 적분 + 데드밴드·마찰은 오차 대신 느린 한계 사이클을 남길 수 있다(PID TL) `[시뮬레이션]`.
- 공칭 1회 성공은 강건성이 아니다. step-nominal n = 30 성공률: LQI 87%, LQR 77%, SMC 50%, PD 계열 10~40% `[시뮬레이션]`. 이 순위는 가정한 파라미터에 민감하다.
- 유실·통신 끊김에는 폴백이 있다. 범위 안의 이상값은 트윈 기본(despike 0 = 펌웨어 1.0.0 동작)에서는 어느 층도 거르지 않고, 1.1.0의 gate는 `filt_mm`만 지킨다(원측정을 쓰는 LQR·LQI·SMC는 그대로). gate를 켜면 sensor-fault에서 PD 계열 성공률이 0~17%에서 30~60%로 오른다 `[시뮬레이션]`.
- 공칭 1회 지표는 이상값 하나에도 크게 흔들린다. PD p1의 트윈 오버슈트 41.3%는 대부분 t = 1.99 s의 이상값 한 개 때문이다(이상값 없이 10.0%, gate로 9.4%) `[시뮬레이션]`. "오버슈트가 커졌다 = 지연 탓"으로 단정하지 않는다.
- 모든 트윈 결과에는 "트윈 파라미터 `[가정]`, 동특성 실측 미검증"을 붙인다.
