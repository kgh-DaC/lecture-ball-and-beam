## 들어가기

01장의 블록선도에서 "제어기 → 서보 → 빔·공 → 센서"를 보았습니다. 이 상자들 사이에서 전기 신호를 주고받는 것이 **아두이노**입니다. 아두이노는 공 위치를 직접 계산하지도, 제어 법칙을 직접 고르지도 않습니다(이 교재에서는 웹 앱이 제어기 역할을 합니다). 아두이노가 하는 일은 세 가지입니다.

1. 센서를 읽는다: 초음파 센서의 에코 시간, 서보 포텐쇼미터 전압
2. 서보에 명령한다: 각도에 해당하는 펄스를 보낸다
3. PC와 이야기한다: 측정값을 보내고 각도 명령을 받는다

이 장은 장치에 상관없는 **아두이노 일반 기초**입니다. 볼앤빔 장치 고유의 설정(Nano와 확장 실드 배선, 서보 별도 전원, CH340 드라이버, 포텐쇼미터 개조)은 [02장](#/ch/02-hardware)에서 다룹니다.

## 1. 마이크로컨트롤러와 아두이노

**마이크로컨트롤러**는 CPU, 메모리, 입출력 회로를 칩 하나에 넣은 작은 컴퓨터입니다. PC처럼 화면이나 운영체제는 없지만, 핀으로 전압을 내보내고 읽을 수 있어서 센서와 모터를 직접 다룹니다. 아두이노는 Atmel(현 Microchip)의 AVR 마이크로컨트롤러에 전원·USB 회로를 붙이고, 무료 개발 도구와 라이브러리를 함께 제공하는 보드입니다 [슬라이드 98].

| 보드 | 마이크로컨트롤러 | 특징 [슬라이드 100, 108~112] |
|---|---|---|
| UNO | ATmega328P | 가장 흔한 입문용, 디지털 14핀(PWM 6), 아날로그 입력 6핀, 16 MHz |
| **Nano** | **ATmega328P** | UNO와 같은 칩을 18 × 45 mm 보드에 넣은 것, 아날로그 입력 8핀 |
| Mega 2560 | ATmega2560 | 핀과 메모리가 많음 |
| NodeMCU | ESP8266 | Wi-Fi 내장(IoT) |

이 교재의 장치는 **Nano 호환 보드**입니다. 칩이 UNO와 같으므로 이 장의 스케치는 UNO에서도 그대로 돌아갑니다(핀 이름이 같습니다). ATmega328P는 플래시 32 KB, SRAM 2 KB, 16 MHz입니다 [슬라이드 109, 110]. PC에 비하면 아주 작지만, 60 ms마다 센서를 읽고 서보를 움직이는 데는 충분합니다.

**이 시스템에서의 의미**: 메모리가 2 KB뿐이라 측정값을 오래 저장할 수 없습니다. 그래서 펌웨어는 측정하자마자 PC로 보내고, 기록·그래프·제어 계산은 PC(웹 앱)가 합니다.

## 2. 다섯 가지 기능과 볼앤빔 부품

마이크로컨트롤러의 기능은 다섯 가지로 나눌 수 있습니다 [슬라이드 101~106]. 볼앤빔의 각 부품이 그중 무엇을 쓰는지 짝지어 봅시다.

![가운데 Arduino Nano. 왼쪽: USB(D0·D1) 시리얼 통신은 PC 웹 앱, D13 디지털 출력은 내장 LED, A0 아날로그 입력은 서보 포텐쇼미터. 오른쪽: D6·D7 디지털 입출력과 시간 재기는 HC-SR04 초음파 센서, D9 타이머·PWM은 서보모터, 인터럽트는 개념만 다룬다](assets/a1-arduino-basics/board-map.svg "그림 1. 마이크로컨트롤러 기능과 볼앤빔 부품의 대응. 실제 배선(실드 헤더, 서보 전원)은 02장 6절.")

| 기능 | 하는 일 | 볼앤빔에서 | 쓰는 함수 |
|---|---|---|---|
| 디지털 출력 | 핀을 0 V 또는 5 V로 | 초음파 Trig 펄스(D6), 내장 LED(D13) | `digitalWrite` |
| 디지털 입력 | 핀이 0 V인지 5 V인지 읽기 | 초음파 Echo(D7)가 HIGH인 시간 | `digitalRead`, `pulseIn` |
| 타이머·PWM | 시간 재기, 정해진 폭의 펄스 반복 | 서보 각도 펄스(D9), 측정 주기 60 ms | `millis`, `Servo.write` |
| 아날로그 입력(ADC) | 0~5 V 전압을 0~1023 숫자로 | 서보 포텐쇼미터 와이퍼(A0) | `analogRead` |
| 시리얼 통신 | 비트를 한 줄로 주고받기 | PC·웹 앱과 측정값·명령 교환(USB) | `Serial.begin/print/read` |
| 인터럽트 | 하던 일을 잠시 멈추고 급한 일 처리 | (이 교재 펌웨어는 쓰지 않음) | `attachInterrupt` |

### 2.1 디지털 입출력

디지털 출력은 프로그램에서 1(HIGH)을 쓰면 핀에 5 V, 0(LOW)을 쓰면 0 V가 나오는 것입니다 [슬라이드 102]. 디지털 입력은 반대로 핀의 전압이 높은지 낮은지를 0/1로 읽습니다.

:::warning
**핀 하나에서 꺼낼 수 있는 전류는 작습니다**(ATmega328P 권장 20 mA, 절대 한계 40 mA [슬라이드 109, 110]). LED는 저항을 거쳐 연결하고, 모터·서보 같은 큰 부하를 핀이나 보드 5V로 직접 돌리지 않습니다. 서보 전원을 따로 두는 이유는 [02장 6.3절](#/ch/02-hardware?h=h-6-3-서보-전원-왜-따로-무엇으로)에서 자세히 봅니다.
:::

### 2.2 타이머와 PWM

타이머는 "시간"을 다룹니다: 기다리기, 지난 시간 재기, 정해진 폭의 펄스를 반복해서 만들기 [슬라이드 104]. 펄스 폭으로 정보를 전하는 방식을 **PWM**(펄스폭 변조)이라고 합니다.

- LED 밝기·DC 모터 속도: 한 주기 중 HIGH 비율(듀티비)로 **평균 전압**을 바꿉니다(`analogWrite`).
- **서보**: 20 ms마다 오는 펄스의 **폭 자체**가 각도 명령입니다(약 0.5~2.4 ms). 평균 전압이 아니라 폭을 읽습니다. 그래서 서보는 `analogWrite`가 아니라 `Servo` 라이브러리로 다룹니다.

펄스폭과 각도의 정확한 관계는 02장에서 다룹니다. 아래 위젯으로 감만 잡아 보세요.

### 2.3 아날로그 입력(ADC)

아두이노에는 아날로그 전압을 **내보내는** 기능(DAC)이 없고, 아날로그 전압을 **읽는** 기능(ADC)만 있습니다 [슬라이드 105]. ATmega328P의 ADC는 10비트라 0~5 V를 $2^{10}$ = 1024 단계(0~1023)로 나눕니다.

$$\text{raw} \approx \frac{V_{in}}{5\ \text{V}} \times 1024 \quad(\text{0~1023에서 잘림}), \qquad 1\ \text{단계} = \frac{5\ \text{V}}{1024} \approx 4.9\ \text{mV}$$

**이 시스템에서의 의미**: 개조한 서보의 포텐쇼미터는 혼 각도에 따라 와이퍼 전압이 바뀝니다. 교수자 장치의 HS-5645MG에서는 약 2.99단계/° [실측: 02장 3.3절]이므로, ADC 한 단계는 서보각 약 0.33°입니다. 서보각을 이보다 잘게 구분할 수는 없습니다.

:::predict p2
A0에 정확히 2.5 V를 걸면 `analogRead(A0)`는 대략 얼마를 돌려줄까요?
:::

### 2.4 시리얼 통신

시리얼 통신은 데이터를 한 비트씩 줄지어 보내는 방식입니다. 선 몇 가닥으로 충분해서 마이크로컨트롤러와 외부 장치 연결에 널리 씁니다(UART, SPI, I2C) [슬라이드 106]. 아두이노와 PC는 USB 케이블 하나로 연결되지만, 보드 안의 USB-시리얼 칩이 이를 UART(D0·D1 핀)로 바꿉니다.

두 쪽이 반드시 맞춰야 하는 것은 **통신 속도(보드레이트)** 입니다. 이 교재 펌웨어는 115200 baud를 씁니다. 한쪽이 9600이고 다른 쪽이 115200이면 비트를 자르는 간격이 달라서 글자가 깨져 보입니다.

### 2.5 인터럽트 (개념만)

인터럽트는 주 작업을 하던 중 버튼 입력 같은 사건이 생기면 잠시 그 일을 처리하고 돌아오는 기능입니다 [슬라이드 103]. 이 교재 펌웨어는 단순하고 시간 순서가 분명하도록 인터럽트를 쓰지 않고, `loop()` 안에서 순서대로 "트리거 → 에코 재기 → A0 읽기 → 보내기"를 합니다. (`Servo` 라이브러리는 내부에서 타이머 인터럽트로 펄스를 만들지만, 우리가 직접 다룰 필요는 없습니다.)

## 3. 개발 환경: IDE와 스케치

### 3.1 설치와 첫 연결

1. Arduino IDE를 `arduino.cc/en/software`에서 내려받아 설치합니다 [슬라이드 119, 120].
2. USB 케이블로 보드를 PC에 연결합니다. 충전 전용 케이블은 통신선이 없어 인식되지 않습니다.
3. **도구 → 보드**에서 보드 종류, **도구 → 포트**에서 COM 포트를 고릅니다 [슬라이드 127].

정품 보드는 대부분 드라이버가 자동으로 잡히지만, 호환 보드는 USB-시리얼 칩(CH340 등) 드라이버를 따로 설치해야 할 수 있습니다 [슬라이드 122~124]. 이 교재 Nano의 드라이버 설치, 보드·프로세서(Old Bootloader) 선택은 [02장 6.4절](#/ch/02-hardware?h=h-6-4-펌웨어-업로드-nano-v3-0-호환-ch340)을 따릅니다.

### 3.2 스케치 구조

아두이노 프로그램을 **스케치**(`.ino`)라고 합니다. 스케치는 같은 이름의 폴더에 저장됩니다 [슬라이드 133].

![왼쪽: 스케치는 전처리(#include, 상수), 전원을 켜면 한 번 실행되는 setup(), 끝없이 반복되는 loop()로 이루어진다. 오른쪽: loop() 한 번은 센서 읽기, 계산, 명령 쓰기, 보고하기의 제어 한 주기이고, delay()보다 millis()로 주기를 지키는 것이 좋다](assets/a1-arduino-basics/sketch-structure.svg "그림 2. 스케치 구조와 loop() 한 번에 하는 일.")

| 부분 | 언제 실행 | 무엇을 쓰나 [슬라이드 128, 130] |
|---|---|---|
| 전처리 | 컴파일 전에 | `#include <Servo.h>`, 핀 번호 상수 |
| `setup()` | 전원을 켜거나 리셋할 때 **한 번** | 핀 입출력 방향, 통신 속도, 서보 연결 |
| `loop()` | `setup()` 다음부터 **끝없이 반복** | 읽기 → 계산 → 쓰기 |

`setup()`과 `loop()`는 내용이 비어 있어도 지우면 안 됩니다 [슬라이드 128].

**이 시스템에서의 의미**: `loop()` 한 번이 제어의 한 주기입니다. 볼앤빔 펌웨어는 `loop()`를 아주 빨리 돌리면서, `millis()`로 60 ms가 지났을 때만 측정·전송을 합니다. 이 60 ms가 01장에서 본 되먹임 경로의 "한 번 보는 간격"이 됩니다.

### 3.3 컴파일과 업로드, 시리얼 모니터

- **컴파일**(✓ 버튼): 코드에 문법 오류가 없는지 확인하고 기계어로 바꿉니다. 오류가 있으면 아래 창에 줄 번호와 내용이 나옵니다 [슬라이드 135, 136].
- **업로드**(→ 버튼): 컴파일한 결과를 보드의 플래시 메모리에 씁니다. 끝나면 보드가 리셋되고 새 프로그램이 바로 실행됩니다 [슬라이드 135].
- **시리얼 모니터**(돋보기 버튼): 보드가 `Serial.print`로 보낸 글을 보고, 글을 보낼 수도 있습니다. 오른쪽 아래 보드레이트를 스케치의 `Serial.begin(…)` 값과 맞춥니다 [슬라이드 137].

:::note
**포트는 한 프로그램만 열 수 있습니다.** 시리얼 모니터가 열려 있으면 업로드도, 웹 앱 연결도 실패합니다. 웹 앱으로 넘어가기 전에 시리얼 모니터를 닫으세요(02장 6.4절 6번).
:::

### 3.4 라이브러리

라이브러리는 특정 부품을 쉽게 쓰도록 미리 만들어 둔 함수 묶음입니다. **스케치 → 라이브러리 포함하기 → 라이브러리 관리**에서 이름으로 찾아 설치하고, 스케치 맨 위에 `#include`로 포함합니다 [슬라이드 138~140]. 이 장에서는 `Servo` 라이브러리를 씁니다(IDE에 기본 포함). 슬라이드 63의 예전 볼앤빔 코드는 `PID_v1` 라이브러리를 썼습니다. PID는 [a2장](#/ch/a2-pid-intro)에서 직접 식으로 봅니다.

## 4. 자주 쓰는 함수

| 함수 | 하는 일 | 예 |
|---|---|---|
| `pinMode(pin, mode)` | 핀을 입력/출력으로 정함 | `pinMode(6, OUTPUT)` |
| `digitalWrite(pin, v)` | 출력 핀을 HIGH(5 V)/LOW(0 V)로 [슬라이드 141] | `digitalWrite(13, HIGH)` |
| `digitalRead(pin)` | 입력 핀 읽기 → HIGH/LOW | |
| `analogRead(pin)` | A0~A7 전압 → 0~1023 | `analogRead(A0)` |
| `millis()` | 전원을 켠 뒤 지난 시간(ms) | 주기 지키기 |
| `delay(ms)`, `delayMicroseconds(us)` | 그 시간 동안 **아무것도 하지 않고** 멈춤 | Trig 10 µs 펄스 |
| `pulseIn(pin, HIGH, timeout_us)` | 핀이 HIGH로 머문 시간(µs). 시간 초과면 0 | 초음파 에코 시간 |
| `Serial.begin(baud)` / `print` / `println` | 통신 시작 / 보내기 | `Serial.begin(115200)` |
| `Serial.available()` / `Serial.read()` | 받은 글자 수 / 한 글자 꺼내기 | PC 명령 받기 |
| `Servo.attach(pin)` / `write(deg)` | 서보 연결 / 각도 명령(0~180°) [슬라이드 61] | `myServo.write(90)` |

:::note
**`delay`와 `pulseIn`은 기다리는 동안 다른 일을 못 합니다.** 슬라이드 64의 예전 볼앤빔 코드는 측정 함수 안에 `delay(40)`과 시간 제한 없는 `pulseIn`을 썼습니다 [슬라이드 64]. 공이 센서 범위 밖에 있으면 `pulseIn`이 기본 1초까지 기다리므로, 그동안 서보 명령이 멈춥니다. 이 교재 펌웨어는 `pulseIn`에 5 ms 시간 제한을 두고, `delay` 대신 `millis()`로 주기를 지킵니다(실습 ⑤).
:::

## 5. 실습: 작은 실험 여섯 개

| 실습 준비 | 내용 |

| 준비물 | Nano(또는 UNO), USB 데이터 케이블, PC(Arduino IDE 설치). ③에는 가변저항 하나(또는 개조 서보의 와이퍼), ④에는 서보와 **별도 5 V 전원**, ⑤에는 HC-SR04 |
| 연결 | 02장 6.2절 배선표의 핀(Trig D6, Echo D7, 서보 D9, 포텐쇼미터 A0)을 그대로 씁니다. ①②⑥은 보드만 있으면 됩니다 |
| 기록할 것 | 각 실험의 시리얼 출력 몇 줄, ③의 raw 최솟값·최댓값, ⑤에서 자로 잰 거리와 측정 거리의 차이 |

:::note
**하드웨어가 없을 때**: 스케치를 컴파일(✓)까지만 해 보고, 시리얼 출력은 아래 "예상 출력"으로 확인합니다. 서보 펄스는 2.2절 위젯, 측정 데이터의 모습은 02장 위젯(가상 장치)으로 봅니다. 아래 스케치는 arduino-cli로 Nano(ATmega328P)용 컴파일을 확인했고, 실제 보드 실행은 교수자 확인 전입니다 [미검증].

### ① Blink: 디지털 출력

```cpp
// ① Blink: 내장 LED(D13)를 0.5초마다 켜고 끈다
void setup() {
  pinMode(LED_BUILTIN, OUTPUT);     // D13을 출력으로
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);  // 5 V 출력 → LED 켜짐
  delay(500);                       // 500 ms 멈춤
  digitalWrite(LED_BUILTIN, LOW);   // 0 V 출력 → LED 꺼짐
  delay(500);
}
```

해 볼 것: `delay` 값을 50으로 바꾸면? 10으로 바꾸면? 어느 순간부터 깜빡임 대신 "어둡게 켜진 것"으로 보입니다. 이것이 PWM으로 LED 밝기를 바꾸는 원리입니다(2.2절).

### ② 시리얼로 PC에 글 보내기

```cpp
// ② 시리얼로 PC에 글 보내기 (시리얼 모니터 115200 baud)
void setup() {
  Serial.begin(115200);                 // 통신 속도: 시리얼 모니터와 같아야 한다
  Serial.println("Hello, ball and beam!");
}

void loop() {
  Serial.print("t_ms = ");
  Serial.println(millis());             // 전원을 켠 뒤 지난 시간(ms)
  delay(1000);
}
```

예상 출력: `Hello, ball and beam!` 다음에 `t_ms = 0`, `t_ms = 1000`, … (값은 조금씩 다를 수 있음).

해 볼 것: 시리얼 모니터의 보드레이트를 일부러 9600으로 바꿔 보세요. 어떤 모습이 되나요? 다시 115200으로 돌려놓습니다.

### ③ analogRead: ADC 분해능 체감

가변저항 양 끝을 5V와 GND에, 가운데(와이퍼)를 A0에 연결합니다. 개조 서보가 있으면 와이퍼 선을 A0에 연결해도 됩니다(와이퍼 전압이 5 V를 넘지 않는지 먼저 확인: [02장 7절](#/ch/02-hardware?h=h-7-서보-개조-포텐쇼미터를-a0에-연결)).

```cpp
// ③ analogRead: A0 전압(0~5 V)을 0~1023 숫자로 읽기
const int POT_PIN = A0;

void setup() {
  Serial.begin(115200);
}

void loop() {
  int raw = analogRead(POT_PIN);        // 0 ~ 1023 (10비트 ADC)
  float volt = raw * 5.0 / 1023.0;      // 숫자 → 전압
  Serial.print(raw);
  Serial.print('\t');
  Serial.println(volt, 3);
  delay(100);
}
```

해 볼 것:
1. 손잡이를 끝까지 돌려 raw가 0과 1023까지 가는지 봅니다.
2. 손을 떼고 가만히 두었을 때 raw가 몇 단계나 흔들리나요? 이 흔들림이 "잡음"입니다. 02장 장치 점검에서는 이것을 σ로 잽니다.
3. IDE의 **도구 → 시리얼 플로터**를 열면 값이 그래프로 보입니다.

### ④ Servo.h로 각도 바꾸기

:::warning
- 서보 빨강선(V+)은 **별도 5.0 V 전원**에, 갈색선(GND)은 그 전원의 −와 보드 GND에 함께(공통 GND), 신호선만 D9에 연결합니다. 큰 서보를 USB 전원(보드 5V 핀)에서 바로 돌리면 보드가 리셋되거나 USB 포트가 상할 수 있습니다([02장 6.3절](#/ch/02-hardware?h=h-6-3-서보-전원-왜-따로-무엇으로)). 9 V 사각 건전지는 쓰지 않습니다.
- 이미 빔에 조립된 서보라면 0°·180°로 돌리면 기구가 부딪힙니다. **혼에서 빔·링크를 떼고** 하거나, 아래 `angles`를 `{80, 90, 100, 90}`처럼 좁혀서 합니다.
:::

```cpp
// ④ Servo.h로 서보 각도 바꾸기: 0° → 90° → 180° → 90°
#include <Servo.h>

const int SERVO_PIN = 9;
Servo myServo;

void setup() {
  Serial.begin(115200);
  myServo.attach(SERVO_PIN);           // 기본: 0° = 544 us, 180° = 2400 us
  myServo.write(90);                   // 가운데에서 시작
  delay(1000);
}

void loop() {
  const int angles[] = {0, 90, 180, 90};
  for (int i = 0; i < 4; i++) {
    myServo.write(angles[i]);
    Serial.print("angle = ");
    Serial.print(angles[i]);
    Serial.print("  pulse_us = ");
    Serial.println(myServo.readMicroseconds());
    delay(1500);
  }
}
```

예상 출력: 각도 0, 90, 180일 때 펄스폭이 약 544, 1472, 2400 µs(라이브러리가 µs를 정수로 맞추므로 몇 µs 차이 날 수 있음). 슬라이드 61의 "−90° ≈ 1.0 ms, 0 ≈ 1.5 ms, +90° ≈ 2.0 ms"는 일반 서보의 대략값이고, `Servo.h` 기본값은 544~2400 µs입니다 [슬라이드 61]. 이 차이는 02장 3.2절에서 다룹니다.

해 볼 것: 서보가 명령한 각도에 **즉시** 가나요, 잠깐 걸리나요? 이 "걸리는 시간"을 07장에서 측정해 모델에 넣습니다.

### ⑤ HC-SR04 거리 재기: `pulseIn`과 `millis` 주기

```cpp
// ⑤ HC-SR04 거리 재기: 60 ms마다 한 번 (millis로 주기 지키기)
const int TRIG_PIN = 6;
const int ECHO_PIN = 7;
const unsigned long PERIOD_MS = 60;   // 센서 권장 측정 주기
unsigned long last_ms = 0;

void setup() {
  Serial.begin(115200);
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
}

void loop() {
  unsigned long now = millis();
  if (now - last_ms < PERIOD_MS) return;   // 아직 때가 아니면 바로 돌아간다
  last_ms = now;

  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);            // 10 us 트리거 펄스
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);

  unsigned long us = pulseIn(ECHO_PIN, HIGH, 5000UL);  // 최대 5 ms만 기다림
  if (us == 0) {                           // 시간 초과 = 측정 실패
    Serial.println("lost");
    return;
  }
  float mm = us * 0.340 / 2.0;             // 340 m/s = 0.340 mm/us, 왕복이라 ÷2
  Serial.println(mm, 1);
}
```

거리 식은 슬라이드 54·55와 같습니다: 거리 = 에코 시간 × 340 m/s ÷ 2 [슬라이드 54, 55]. 원리와 센서 한계(분해능 3 mm, 60 ms 주기, 유효각)는 [02장 4절](#/ch/02-hardware?h=h-4-1-원리)에서 봅니다.

해 볼 것:
1. 손바닥이나 책을 100, 200, 300 mm에 두고 자로 잰 값과 비교합니다.
2. 센서 앞을 비우면 `lost`가 나오나요? 5 ms 시간 제한 덕분에 측정이 실패해도 `loop()`가 오래 멈추지 않습니다.
3. `PERIOD_MS`를 10으로 줄이면 값이 이상해지나요? 앞의 반사파가 다음 측정에 섞이기 때문입니다 [슬라이드 54].

:::predict p3
에코 핀이 1.2 ms 동안 HIGH였습니다. 물체까지 거리는 몇 mm일까요? (음속 340 m/s)
:::

### ⑥ PC에서 명령 보내기

지금까지는 보드가 PC에 **보내기만** 했습니다. 이번에는 PC가 보낸 글자를 받아 행동합니다 [슬라이드 78].

```cpp
// ⑥ PC에서 명령 받기: '1' → LED 켬, '0' → LED 끔
void setup() {
  Serial.begin(115200);
  pinMode(LED_BUILTIN, OUTPUT);
  Serial.println("send 1 (on) or 0 (off)");
}

void loop() {
  while (Serial.available() > 0) {         // 받은 글자가 있으면
    char c = Serial.read();                // 한 글자 꺼내기
    if (c == '1') { digitalWrite(LED_BUILTIN, HIGH); Serial.println("LED ON"); }
    else if (c == '0') { digitalWrite(LED_BUILTIN, LOW); Serial.println("LED OFF"); }
  }
}
```

시리얼 모니터 입력 칸에 `1`, `0`을 보내 봅니다. 슬라이드 78처럼 파이썬(`pyserial`)으로 보내도 똑같이 동작합니다 [슬라이드 77, 78].

**바로 이것이 우리 웹 앱이 하는 일입니다.** 볼앤빔 펌웨어는 60 ms마다 "측정값 한 줄"을 PC로 보내고(⑤ + ②), 웹 앱은 그 값으로 제어 법칙을 계산해 "각도 명령 한 줄"을 보내며, 펌웨어는 그 명령을 받아 서보를 움직입니다(⑥ + ④). 주고받는 줄의 형식(프로토콜)과 앱 없이 통신을 확인하는 도구는 [02장 6.6절](#/ch/02-hardware?h=h-6-6-앱-없이-통신-확인-tools-serial-check-py)에서 봅니다.

|---|---|---|
| ③ 가만히 둬도 raw가 몇 단계 흔들림 | 측정에는 항상 잡음이 있다 | 02장 장치 점검(σ), 거리 필터 |

## 생각해 보기

채점하지 않는 질문입니다. 답을 먼저 적어 보고, 막히면 아래 실마리를 열어 보세요.

1. 5 V 기준 10비트 ADC에서 A0에 2.5 V를 걸면 `analogRead` 값은 대략? 한 단계는 몇 mV인가?
2. HC-SR04의 에코가 1.2 ms 동안 HIGH였다. 음속 340 m/s로 거리(mm)는?
3. `setup()`과 `loop()`의 차이는? 핀 방향 설정을 `loop()`에 넣으면 어떻게 되나?
4. 스케치는 `Serial.begin(115200)`인데 시리얼 모니터가 9600이면 어떤 증상이 보이나?
5. 서보를 보드 5V 핀에서 바로 구동하면 어떤 일이 생길 수 있나?
6. `loop()` 안에서 `delay(40)`과 시간 제한 없는 `pulseIn`을 쓰는 코드(슬라이드 64)의 문제는 무엇인가?

:::details 생각의 실마리 (스스로 답을 적어 본 뒤 열기)
1. raw ≈ 2.5/5 × 1024 = 512(구현에 따라 511~512). 한 단계 = 5/1024 V ≈ 4.9 mV.
2. 거리 = 0.0012 s × 340 m/s ÷ 2 = 0.204 m = 204 mm. 2로 나누는 것은 왕복이기 때문.
3. `setup()`은 전원을 켤 때 한 번, `loop()`는 끝없이 반복. 핀 설정을 `loop()`에 넣어도 동작은 하지만 매번 같은 일을 반복해 시간을 낭비하고, 통신 시작(`Serial.begin`)을 반복하면 통신이 끊길 수 있다. 한 번이면 되는 일은 `setup()`에.
4. 글자가 깨지거나(이상한 기호) 아무것도 안 보인다. 비트를 자르는 시간 간격이 달라서다. 웹 앱 연결이 안 될 때도 펌웨어 보드레이트(115200)를 먼저 확인한다.
5. 서보가 순간적으로 큰 전류를 끌어 보드 5 V가 처지고, 보드가 리셋되거나 센서·A0 값이 흔들린다. 심하면 USB 포트나 보드가 상한다. 그래서 별도 5.0 V 전원 + 공통 GND(02장 6.3절).
6. 기다리는 동안 다른 일을 못 한다. 공이 범위 밖이면 `pulseIn`이 최대 1초 기다려 그동안 서보 명령이 멈춘다. 측정 간격도 계산 시간에 따라 들쭉날쭉해진다. `millis()`로 주기를 지키고 `pulseIn`에 시간 제한을 둔다.
:::

## 요약과 다음 챕터

- 아두이노(Nano, ATmega328P)는 볼앤빔에서 센서 읽기, 서보 명령, PC 통신을 맡고, 제어 계산은 웹 앱이 한다.
- 디지털 입출력(Trig·Echo), 타이머·PWM(서보 펄스, 60 ms 주기), ADC(포텐쇼미터 0~1023), 시리얼(115200 baud)이 각각 부품과 짝을 이룬다.
- 스케치 = 전처리 + `setup()`(한 번) + `loop()`(반복). `loop()` 한 번이 제어 한 주기이고, `delay` 대신 `millis()`로 주기를 지킨다.
- 시리얼로 "측정값 보내기 + 명령 받기"를 하면 그것이 웹 앱과 펌웨어의 대화가 된다.
